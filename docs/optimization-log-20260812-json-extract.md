# LINK 信息提取重构：正则 → 大模型 JSON 结构化提取

**日期**：2026-08-12
**起因**：用户指出正则匹配提取用户信息的方案局限大，建议用 JSON 结构体让大模型评判输入内容

---

## 一、正则方案的局限（用户洞察）

`_regex_extract_facts` 用正则匹配用户输入提取信息，局限明显：

| 场景 | 正则表现 |
|------|---------|
| "我叫李华" | ✅ 提取 `用户叫李华` |
| "我叫王强，喜欢打篮球" | ❌ 吞并标点 → `用户叫王强，喜欢打`（已修复但治标） |
| "我是数据分析师" | ❌ 不匹配（结尾无 工程师/设计师 等词） |
| "我在上海工作" | ❌ 完全不覆盖 |
| "1995年出生" / "毕业于清华大学" | ❌ 完全不覆盖 |

正则只能处理固定句式，无法应对复杂、自然、多样的表达。

## 二、新方案：大模型 Function Calling 结构化提取

采纳用户建议（JSON 结构化），用**已存在的 Function Calling 机制**实现：

1. **新增 `extract_user_facts` 工具**（EXTRACT_FACTS_TOOL，不暴露给主对话循环）：
   - 模型返回 `{facts: [{category, value, confidence}]}` JSON
   - Function Calling 原生 JSON 校验，无格式漂移
   - 类别枚举：姓名/职业/偏好/手机号/邮箱/生日/地址/年龄/技能/项目/其他

2. **`_extract_facts_from_conversation` 改造**：
   - 优先用工具提取（覆盖复杂表述）
   - 正则降级为**兜底**（仅工具提取失败/无个人信息信号时）
   - 正则保留"信号检测"功能（判断是否值得调 LLM，避免每次对话都调）

3. **记忆系统配合**：
   - 提取结果存 `用户{类别}: {值}` 格式（与 save_user_fact 一致，利于去重）
   - 修复 `_extract_fact_category` 缺年龄/技能/项目/其他类别导致去重失效
   - `_find_duplicate_fact` 对无类别事实也做完全相同去重
