# LINK 记忆重复深层根因分析 + 修复日志

**日期**：2026-08-12
**目标**：深挖记忆重复的根本原因（不止表面修复），修复深层问题

---

## 一、为什么会出现重复记忆？（4 个深层根源）

用户信息类事实有三个保存来源，且格式不同：正则提取（`用户叫陈晨`）、LLM 提取（`姓名：陈晨`）、`save_user_fact` 工具（`用户姓名: 陈晨`）。但深入追踪发现**4 个叠加的深层问题**：

### 根源 1（最核心）：正则吞并 bug
`_regex_extract_facts` 的姓名/职业/偏好正则用 `\S{2,6}` / `.{2,24}` **贪婪匹配**：

```
我叫王强，喜欢打篮球  →  提取成 "用户叫王强，喜欢打"  ❌
```

`\S` 匹配了逗号和后续内容。后果：
- 产生**损坏事实**（`用户叫王强，我的职`）
- 每轮提取结果不同（`王强，喜欢打` / `王强，我的职`）→ **格式漂移本身就是重复的来源**

### 根源 2：函数内无语义去重
`_extract_facts_from_conversation` 的 `clean_facts` 仅按**完全相同**去重，正则的 `用户叫陈晨` 与 LLM 的 `姓名：陈晨` 同时进入 → 同一轮就存两条。

### 根源 3：LLM 提取每次对话都调 API
`_extract_facts_from_conversation` **每次对话**都调 LLM 提取事实，即使输入无个人信息（如"你好"）。既浪费成本，又持续产生格式漂移的提取结果。

### 根源 4：矛盾删除误判
`_remove_contradicting_facts` 用 `m.content not in new_facts`（完全相等）判断，导致：同类别不同格式的重复事实**不被删除**（误以为不同），真正矛盾（职业从A变B）才删的逻辑也不准。

## 二、修复

| 根源 | 修复 |
|------|------|
| 正则吞并 | 姓名/职业/偏好正则排除标点 `[^，。,!！?？、\s]`，只匹配核心值 |
| 函数内无语义去重 | 新增 `_facts_semantically_equal`（同类别+核心值相似），clean_facts 内合并 |
| LLM 每轮调API | 预检个人信息信号（`我叫/我是/我喜欢/我的职业` 等），无信号跳过 LLM |
| 矛盾删除误判 | `_remove_contradicting_facts` 用语义判断：值不同（真矛盾）才删旧 |

另外：LLM 提取 prompt 改为标准格式 `用户{类别}: {值}`，与正则/save_user_fact 统一。
