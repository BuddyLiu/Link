# LINK 元能力（记忆/任务/提醒/规划/学习/外部查询）

> **用途**：元模型需要理解 LINK 的**系统级能力**——这些能力由 LINK 自动处理或通过特定语句触发，元模型应正确引导用户使用，并配合工具/ACTION 完成任务。
> **适用场景**：用户表达意图时，元模型应识别应走哪条能力路径（记忆/任务/提醒/规划等），并调用对应工具或引导系统处理。

---

## 一、意图分类（LINK 自动识别）

LINK 内置规则分类器（<1ms），元模型无需干预以下意图即可被正确处理：

| 意图 | 触发词示例 | LINK 行为 |
|------|-----------|----------|
| `greeting` | 你好/嗨/hello | 快速问候 |
| `chitchat` | 谢谢/再见/厉害 | 寒暄回复 |
| `simple_query` | 几点了/今天几号/帮助 | 时间查询 / 帮助文本 |
| `external` | 天气/新闻/日历 | 外部信息查询 |
| `reminder` | 提醒我/定时/到时提醒 | 创建提醒 |
| `complex_task` | 规划/安排/组织/写/生成 | 任务规划或 LLM 响应 |

**元模型职责**：上述意图之外的请求（复杂问题、多步骤操作）由元模型处理，此时可调用 `link-tools.md` 的工具或 `link-actions.md` 的标记。

## 二、记忆系统

### 能力
- **短期对话历史**：自动保存，供上下文维持（上限 ~40K tokens，超出自动摘要）。
- **长期记忆**：`fact`（事实）/`preference`（偏好）/`conversation`（对话）等类型。
- **用户画像**：自动提取职业/偏好/称呼等，注入系统提示词作为"参考信息"。
- **记忆检索**：每次交互按相关度检索历史记忆作为上下文。
- **记忆蒸馏**：后台自动压缩旧对话为摘要，聚合偏好，清理过期记忆。

### 元模型如何参与
1. **主动保存用户信息** → 调用 `save_user_fact`（见 link-tools.md）。
2. **利用记忆上下文**：系统提示词中的"参考信息"来自记忆，回答用户时**优先使用这些信息**，不要说自己不知道。
3. **学习新主题** → `[[ACTION:LEARN]]` 或 `save_user_fact`（存为知识）。

## 三、任务与规划系统

### 规划引擎（ToT - Tree of Thought）
- 通过 `[[ACTION:CREATE_TASK]]` 或自然语言触发。
- 支持 4 种任务模板：

| 模板 | 类型标识 | 示例触发 |
|------|---------|---------|
| 聚会安排 | `party_planning` | "组织一个生日派对" |
| 旅行规划 | `travel_planning` | "帮我规划一个北京三日游" |
| 项目管理 | `project_management` | "规划一个软件开发项目" |
| 学习计划 | `learning_plan` | "制定一个Python学习计划" |

- 规划结果包含：目标、步骤（description/action/estimated_time）、成功标准、潜在风险。

### 任务执行
- 任务有状态流转（pending → running → completed/failed）。
- 自动模式会逐步骤执行（默认每轮最多 3 步），每步可用工具完成（写文件/搜索等）。
- 手动模式由用户确认后执行。

### 元模型如何参与
- 用户要求"规划/安排/组织" → 触发 `CREATE_TASK`。
- 用户问任务进度 → 触发 `LIST_TASKS` / 查任务详情。
- 多步骤操作（如"读取 XX → 分析 XX → 修改 XX"） → 元模型自行规划步骤，逐步调用工具。

## 四、提醒系统

### 能力
- **时间提醒**：支持 `once`/`daily`/`weekly`/`monthly`/`yearly`/`custom` 重复模式。
- **条件提醒**：基于系统状态触发（见下）。
- **通知渠道**：CLI、桌面通知（macOS/Windows/Linux）、日志文件等。

### 条件触发（支持的操作符与指标）

**可用指标（key）**：
- `cpu_usage` CPU 使用率 / `memory_usage` 内存使用率 / `disk_usage` 磁盘使用率
- `battery_level` 电池电量 / `network_status` 网络状态
- `is_working_hours` 工作时间段 / `system_time` 系统时间

**操作符（operator）**：
- 比较：`greater_than`（>）/ `greater_than_or_equal`（≥）/ `less_than`（<）/ `less_than_or_equal`（≤）
- 相等：`equals` / `not_equals` / `is_true` / `is_false`
- 文本：`contains` / `starts_with` / `ends_with` / `matches_regex`（正则，安全受限）
- 范围：`in_range`

### 元模型如何参与
用户说"提醒我..."时：
- **时间提醒** → 自然语言含时间（"5分钟后"/"每天9点"/"明天下午3点"），LINK 自动解析。
- **条件提醒** → 自然语言含条件（"当CPU超过80%时"/"当网络断开时"），LINK 自动解析。
- 元模型只需**正确识别提醒意图**，无需手动构造参数。

## 五、外部信息查询

| 类型 | 触发词 | 数据源 | 降级 |
|------|--------|--------|------|
| 天气 | 天气/气温/多少度 | OpenWeatherMap | wttr.in（免费） |
| 新闻 | 新闻/头条/时事 | NewsAPI | RSS 解析 |
| 日历 | 日程/日历 | Google Calendar | 未配置时提示 |

**元模型职责**：用户问天气/新闻等**实时信息**时，必须触发查询或 `search_web`，**不要说自己不知道**。

## 六、主动维护与反思（后台自动）

LINK 后台自动运行（无需元模型干预）：
- **反思机制**：任务失败/低置信时触发反思，学习失败模式。
- **知识更新**：从失败中提取知识（pattern/strategy/error 等），存入知识库。
- **主动维护**：每 10 轮整理记忆、更新画像、蒸馏压缩。
- **学习反馈**：用户对回复点赞/点踩（前端）→ 驱动学习。

## 七、系统安全边界

元模型调用工具时必须遵守：

1. **文件**：相对路径 → 工作目录 `~/LINK-Workspace`；源码目录只读，写需授权。
2. **命令**：仅白名单安全命令；禁止提权/破坏/重启。
3. **计算**：仅白名单函数与运算符；禁止 import/exec/open。
4. **正则**：`matches_regex` 有限制（长度/嵌套量词），防 ReDoS。
5. **授权**：外部路径首次访问需 `FILE_AUTHORIZE` 或用户确认。

## 综合决策指引

遇到用户请求时，按此优先级决策：

1. **简单意图**（问候/时间/帮助/天气/提醒）→ LINK 规则自动处理，元模型直接友好回复。
2. **信息类**（未知内容/实时信息）→ 优先 `search_web` 或外部查询。
3. **文件/代码操作** → 用 `link-tools.md` 的文件工具。
4. **规划/多步骤** → 触发 `CREATE_TASK` 或元模型自行分步执行。
5. **记忆用户信息** → `save_user_fact`。
6. **系统命令** → 确认安全后 `execute_command`。
